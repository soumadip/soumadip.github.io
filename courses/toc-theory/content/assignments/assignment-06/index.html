Assignment 6: Pushdown Automata and Deterministic Parsing

This assignment evaluates and deepens your understanding of Pushdown Automata (PDAs), nondeterministic versus deterministic computation, equivalence with Context-Free Grammars (CFGs), Deterministic Context-Free Languages (DCFLs), and deterministic parsing principles, synthesizing Michael Sipser (Chapters 2.2 & 2.4) and Peter Linz (Chapter 7).

Section A: True or False Questions

For each question, select True or False and provide a rigorous mathematical justification.

Question 1

In a Pushdown Automaton (PDA), acceptance by final state and acceptance by empty stack are equivalent in power for nondeterministic PDAs (NPDAs). However, for Deterministic PDAs (DPDAs) without an explicit endmarker, acceptance by empty stack recognizes a strictly smaller class of languages than acceptance by final state (specifically, prefix-free DCFLs).

💡 View Solution

Answer: True

Justification:

  • For NPDAs: Any language accepted by final state can be converted to an equivalent NPDA accepting by empty stack (and vice versa) by adding initial/final helper states and using \(\varepsilon\)-transitions to clear the stack or push a bottom-marker. Thus, \(N(M_{empty}) = L(M_{final}) = \text{CFL}\).
  • For DPDAs without endmarkers: If a DPDA accepts a string \(w\) by empty stack, the stack becomes completely empty upon reading \(w\). By definition of a PDA’s transition function, no further transitions can be executed from an empty stack without popping a symbol (which is impossible). Thus, if \(w \in L(M_{empty})\), no proper extension \(w x\) (where \(x \neq \varepsilon\)) can ever be processed or accepted. Consequently, any language accepted by empty stack in a DPDA must satisfy the prefix property (no string in the language is a proper prefix of another string in the language).
  • Since general DCFLs (such as \(L = {a, aa}\)) do not necessarily possess the prefix property, acceptance by empty stack recognizes a strictly smaller class of languages (prefix-free DCFLs) unless an explicit endmarker symbol (such as \(\dashv\) or \($\)) is appended to every input string.

Question 2

The class of Deterministic Context-Free Languages (DCFLs) is closed under union, intersection, and complementation, matching the closure properties of regular languages.

💡 View Solution

Answer: False

Justification: While DCFLs are closed under complementation (Sipser Theorem 2.42), they are NOT closed under union or intersection.

  • Counterexample for Union: Consider the languages: \[L_1 = {a^n b^n c^m \mid n, m \geq 0} \quad \text{and} \quad L_2 = {a^n b^m c^m \mid n, m \geq 0}\] Both \(L_1\) and \(L_2\) are DCFLs because a DPDA can easily count \(a\)’s vs \(b\)’s (for \(L_1\)) or \(b\)’s vs \(c\)’s (for \(L_2\)) deterministically. However, their union: \[L_1 \cup L_2 = {a^i b^j c^k \mid i = j \text{ or } j = k}\] is a non-deterministic CFL because a PDA must guess at the very beginning whether to match \(a\)’s against \(b\)’s or \(b\)’s against \(c\)’s before reading the \(c\)’s.
  • Counterexample for Intersection: \(L_1 \cap L_2 = {a^n b^n c^n \mid n \geq 0}\), which is not even a Context-Free Language.

Question 3

The regular languages form a proper subset of Deterministic Context-Free Languages (\(Regular \subset DCFL\)), which in turn form a proper subset of Context-Free Languages (\(DCFL \subset CFL\)).

💡 View Solution

Answer: True

Justification:

  1. \(Regular \subset DCFL\): Any Deterministic Finite Automaton (DFA) can be viewed as a DPDA that simply ignores its stack (or never pushes symbols). Thus, every regular language is a DCFL. The inclusion is proper because \(L_{eq} = {a^n b^n \mid n \geq 0}\) is a DCFL (recognized by a simple DPDA) but is non-regular.
  2. \(DCFL \subset CFL\): Every DPDA is by definition a specialized NPDA (where transition choices are restricted to at most 1 option). Thus, every DCFL is a CFL. The inclusion is proper because \(L_{pal} = {w w^R \mid w \in {a, b}^*}\) is a context-free language (generated by \(S \to aSa \mid bSb \mid \varepsilon\)), but it cannot be recognized by any DPDA because locating the midpoint of \(w w^R\) without a middle-marker requires nondeterministic guessing.

Question 4

In the standard top-down CFG-to-PDA conversion algorithm (simulating a leftmost derivation on the stack), when a variable \(A\) is on top of the stack, the PDA nondeterministically selects a production rule \(A \to w\) and pushes \(w\) onto the stack in reverse order.

💡 View Solution

Answer: True

Justification: The stack operates as a Last-In, First-Out (LIFO) data structure. To simulate a leftmost derivation, the leftmost symbol of the production body \(w = s_1 s_2 \dots s_k\) must end up on the very top of the stack so that it can be expanded or matched against the input first. Pushing \(w\) symbol-by-symbol from right to left (\(s_k\) first, down to \(s_1\) last) ensures that \(s_1\) resides at the top of the stack. Therefore, \(w\) must be written in reverse order onto the stack.

Question 5

Let \(M = (Q, \Sigma, \Gamma, \delta, q_0, z_0, F)\) be a Pushdown Automaton. Which of the following mathematical conditions are strictly required for \(M\) to be classified as a Deterministic Pushdown Automaton (DPDA)? (Select all that apply)

  • Options:
    • A) For every \(q \in Q\), \(a \in \Sigma \cup {\varepsilon}\), and \(X \in \Gamma\), the transition set contains at most one element (\(|\delta(q, a, X)| \le 1\)).
    • B) For every \(q \in Q\) and \(X \in \Gamma\), if \(\delta(q, \varepsilon, X) \neq \emptyset\), then \(\delta(q, a, X) = \emptyset\) for all \(a \in \Sigma\).
    • C) The stack must be emptied completely whenever the machine enters an accepting state \(q \in F\).
    • D) The machine must not contain any \(\varepsilon\)-transitions under any circumstances.
💡 View Solution

Correct Options: A, B

Justification:

  • A is correct: Determinism mandates that at any step in a computation, there is at most one legal move available. Thus, \(|\delta(q, a, X)| \le 1\).
  • B is correct: If an input-free move (\(\varepsilon\)-move) is defined for a configuration \((q, \varepsilon, X)\), no input-consuming transition \(\delta(q, a, X)\) can be allowed for any \(a \in \Sigma\). Otherwise, when scanning input symbol \(a\) with \(X\) on top of the stack, the machine would face a nondeterministic choice between making the \(\varepsilon\)-move or reading \(a\).
  • C is incorrect: Acceptance for a DPDA by final state requires only that the machine enters state \(q \in F\) after reading the last symbol of the input string. The stack contents upon reaching \(F\) are irrelevant for acceptance by final state.
  • D is incorrect: Unlike DFAs, DPDAs are allowed to have \(\varepsilon\)-transitions (e.g., to pop or manipulate stack contents without consuming input), provided Condition B is strictly satisfied so that determinism is preserved.

Question 6

Which of the following Context-Free Languages are Deterministic Context-Free Languages (DCFLs)? (Select all that apply)

  • Options:
    • A) \(L_1 = {a^n b^n \mid n \geq 0}\)
    • B) \(L_2 = {w c w^R \mid w \in {a, b}^*}\)
    • C) \(L_3 = {w w^R \mid w \in {a, b}^*}\)
    • D) \(L_4 = {a^i b^j c^k \mid i, j, k \geq 0 \text{ and } (i = j \text{ or } i = k)}\)
💡 View Solution

Correct Options: A, B

Justification:

  • A is a DCFL: A DPDA pushes all \(a\)’s onto the stack and then deterministically switches to popping one \(a\) for each \(b\) read.
  • B is a DCFL: The explicit center marker \(c\) signals the exact midpoint of the string. The DPDA pushes \(w\) onto the stack, and upon reading \(c\), deterministically switches state to match \(w^R\) symbol-by-symbol against the popping stack.
  • C is NOT a DCFL: Lacking a center marker, the machine must nondeterministically guess where \(w\) ends and \(w^R\) begins. Formally proved non-deterministic in Sipser Problem 2.58 and Linz Section 7.3.
  • D is NOT a DCFL: The machine cannot know in advance whether to match \(a\)’s against \(b\)’s or \(a\)’s against \(c\)’s. Its complement is not context-free, which proves \(L_4\) cannot be a DCFL because DCFLs are closed under complementation.

Question 7 (NPDA Design and Configuration Trace)

Design a Nondeterministic Pushdown Automaton \(M = (Q, \Sigma, \Gamma, \delta, q_0, z, F)\) that accepts the language: \[L = {a^n b^m \mid 1 \leq n \leq m \leq 2n}\]

  1. Explain the stack strategy used to enforce the counting relationship \(n \leq m \leq 2n\).
  2. Provide the formal 7-tuple specification and list all transition rules.
  3. Trace the sequence of Instantaneous Descriptions (IDs) / configurations for the input string \(w = aabbb\).
💡 View Solution

Step 1: Stack Strategy

The condition \(n \leq m \leq 2n\) means that for every \(a\) read, we must read at least 1 \(b\) and at most 2 \(b\)’s.

  • When reading an \(a\), we push a marker symbol \(X\) onto the stack.
  • When reading \(b\)’s, each \(a\) (represented by an \(X\) on the stack) can match either one \(b\) or two \(b\)’s.
  • We use nondeterminism when reading \(b\)’s: for each \(X\) popped from the stack, the machine can either consume one \(b\) or consume two \(b\)’s (by executing an extra step consuming \(b\)).

Step 2: Formal 7-Tuple & Transitions

Let \(M = (Q, \Sigma, \Gamma, \delta, q_0, z, {q_3})\) where:

  • \(Q = {q_0, q_1, q_2, q_3}\)
  • \(\Sigma = {a, b}\)
  • \(\Gamma = {X, z}\)
  • \(q_0\) is the start state, \(z\) is the stack start symbol, \(F = {q_3}\).

Transition Rules \(\delta\):

  1. Pushing phase (reading \(a\)’s):

    • \(\delta(q_0, a, z) = {(q_0, Xz)}\)
    • \(\delta(q_0, a, X) = {(q_0, XX)}\)

  2. Transition to matching phase:

    • \(\delta(q_0, b, X) = {(q_1, \varepsilon), (q_2, \varepsilon)}\) (Nondeterministic branch: \(q_1\) matches one \(b\) per \(X\); \(q_2\) handles a second \(b\) for the same \(X\))

  3. Matching phase (\(q_1\) and \(q_2\)):

    • \(\delta(q_1, b, X) = {(q_1, \varepsilon), (q_2, \varepsilon)}\)
    • \(\delta(q_2, b, X) = {(q_1, X)}\) (Consumes a second \(b\) while keeping \(X\) on stack to be popped next)
    • \(\delta(q_1, \varepsilon, z) = {(q_3, z)}\)
    • \(\delta(q_2, \varepsilon, z) = {(q_3, z)}\)

Step 3: Trace of Configurations for \(w = aabbb\)

Here \(n = 2\), so \(m = 3\) satisfies \(2 \le 3 \le 4\).

\[\begin{aligned} (q_0, aabbb, z) &\vdash (q_0, abbb, Xz) && \text{(push } X\text{)} \ &\vdash (q_0, bbb, XXz) && \text{(push } X\text{)} \ &\vdash (q_1, bb, Xz) && \text{(read 1st } b\text{, pop 1st } X \text{ going to } q_1\text{)} \ &\vdash (q_2, b, z) && \text{(read 2nd } b\text{, pop 2nd } X \text{ going to } q_2\text{)} \ &\vdash (q_1, \varepsilon, z) && \text{(read 3rd } b\text{ from } q_2\text{, stack top is } z\text{)} \ &\vdash (q_3, \varepsilon, z) && \text{(transition to accept state } q_3\text{)} \end{aligned}\]

Since the input is fully consumed and the machine reaches \(q_3 \in F\), the string \(aabbb\) is accepted.

Question 8 (CFG to NPDA Conversion)

Consider the Context-Free Grammar \(G = (V, T, S, P)\) with \(V = {S, A}\), \(T = {a, b}\), start symbol \(S\), and productions: \[S \to a S b \mid A\] \[A \to a A \mid \varepsilon\]

  1. Convert \(G\) into an equivalent single-state NPDA \(M\) using the top-down (leftmost derivation) algorithm.
  2. List the full transition function \(\delta\) of \(M\).
  3. Trace the computation (stack contents and unread input) of \(M\) accepting the string \(w = aab\).
💡 View Solution

Step 1 & 2: Top-Down NPDA Construction

We construct the 3-state helper NPDA \(M = (Q, \Sigma, \Gamma, \delta, q_{start}, z, {q_{accept}})\) (or 1-looping state \(q_{loop}\) format):

  • \(Q = {q_{start}, q_{loop}, q_{accept}}\)
  • \(\Sigma = {a, b}\)
  • \(\Gamma = {S, A, a, b, $}\)
  • Start state: \(q_{start}\), Stack bottom marker: \($\), Accept state: \(q_{accept}\).

Transition Rules \(\delta\):

  1. Initialize stack with start variable \(S\): \[\delta(q_{start}, \varepsilon, \varepsilon) = {(q_{loop}, S$)}\]

  2. Variable expansion transitions (rule matching on \(q_{loop}\)):

    • For \(S \to a S b\): \(\delta(q_{loop}, \varepsilon, S) \gets (q_{loop}, aSb)\)
    • For \(S \to A\): \(\delta(q_{loop}, \varepsilon, S) \gets (q_{loop}, A)\)
    • For \(A \to a A\): \(\delta(q_{loop}, \varepsilon, A) \gets (q_{loop}, aA)\)
    • For \(A \to \varepsilon\): \(\delta(q_{loop}, \varepsilon, A) \gets (q_{loop}, \varepsilon)\)

  3. Terminal matching transitions:

    • \(\delta(q_{loop}, a, a) = {(q_{loop}, \varepsilon)}\)
    • \(\delta(q_{loop}, b, b) = {(q_{loop}, \varepsilon)}\)

  4. Acceptance transition:

    • \(\delta(q_{loop}, \varepsilon, $) = {(q_{accept}, \varepsilon)}\)

Step 3: Computation Trace for \(w = aab\)

We trace the leftmost derivation of \(aab\): \(S \Rightarrow aSb \Rightarrow aAb \Rightarrow aaAb \Rightarrow aab\).

\[\begin{aligned} (q_{start}, aab, \varepsilon) &\vdash (q_{loop}, aab, S$) && \text{(initialize stack with } S$\text{)} \ &\vdash (q_{loop}, aab, aSb$) && \text{(expand } S \to aSb\text{)} \ &\vdash (q_{loop}, ab, Sb$) && \text{(match terminal } a\text{)} \ &\vdash (q_{loop}, ab, Ab$) && \text{(expand } S \to A\text{)} \ &\vdash (q_{loop}, ab, aAb$) && \text{(expand } A \to aA\text{)} \ &\vdash (q_{loop}, b, Ab$) && \text{(match terminal } a\text{)} \ &\vdash (q_{loop}, b, b$) && \text{(expand } A \to \varepsilon\text{)} \ &\vdash (q_{loop}, \varepsilon, $) && \text{(match terminal } b\text{)} \ &\vdash (q_{accept}, \varepsilon, \varepsilon) && \text{(accept on empty stack / marker)} \end{aligned}\]

Question 9 (DPDA and Complementation)

Let \(L = {a^n b^n \mid n \geq 1}\).

  1. Construct a formal DPDA \(M\) that accepts \(L\) by final state and reads the entire input string on all inputs.
  2. Modify \(M\) to construct a DPDA \(M^c\) that accepts the complement language \(\bar{L} = \Sigma^* - L\).
  3. Explain why unread input or infinite \(\varepsilon\)-loops break simple state-swapping in DPDAs, and how your construction avoids these pitfalls.
💡 View Solution

Part 1: DPDA for \(L = {a^n b^n \mid n \geq 1}\) Reading Full Input

To ensure the DPDA reads the entire input string without hanging or trapping in unread states:

  • We introduce a dedicated dead state \(q_{dead}\) to handle out-of-order characters (e.g., \(a\) after \(b\), or \(b\) before \(a\)).
  • We initialize the stack with \(Z_0\).

DPDA \(M = (Q, \Sigma, \Gamma, \delta, q_0, Z_0, {q_3})\):

  • \(Q = {q_0, q_1, q_2, q_3, q_{dead}}\)
  • \(\Sigma = {a, b}\), \(\Gamma = {X, Z_0}\)

Transitions:

  • \(\delta(q_0, a, Z_0) = (q_1, X Z_0)\)
  • \(\delta(q_1, a, X) = (q_1, X X)\)
  • \(\delta(q_1, b, X) = (q_2, \varepsilon)\)
  • \(\delta(q_2, b, X) = (q_2, \varepsilon)\)
  • \(\delta(q_2, \varepsilon, Z_0) = (q_3, Z_0)\) (Move to accept state \(q_3\) when stack matches)
  • Any illegal transition (e.g., \(b\) in \(q_0\), \(a\) in \(q_2\), or extra \(b\) when top is \(Z_0\)) transitions to \(q_{dead}\) and consumes remaining input.
    • \(\delta(q_0, b, Z_0) = (q_{dead}, Z_0)\)
    • \(\delta(q_2, a, X) = (q_{dead}, X)\)
    • \(\delta(q_3, a, Z_0) = (q_{dead}, Z_0)\)
    • \(\delta(q_3, b, Z_0) = (q_{dead}, Z_0)\)
    • \(\delta(q_{dead}, a, \text{any}) = (q_{dead}, \text{same})\)
    • \(\delta(q_{dead}, b, \text{any}) = (q_{dead}, \text{same})\)

Part 2: Construction of Complement DPDA \(M^c\)

Since \(M\) is deterministic and guaranteed to read the entire input string without looping or hanging:

  • The complement DPDA \(M^c\) has the exact same state set, stack alphabet, and transition function \(\delta\).
  • We simply swap the accept and non-accept states among all reading states: \[F^c = Q - F = {q_0, q_1, q_2, q_{dead}}\]

Part 3: Why Simple State-Swapping Fails Without Input Guarantee

If a DPDA \(M_0\) fails to read the entire input string (e.g., it hangs by popping an empty stack or enters an infinite \(\varepsilon\)-loop before finishing the string), \(M_0\) rejects the input.

  • If we simply swap accept/non-accept states, the machine will still hang or loop infinitely on that input, thus rejecting it again in \(M_0^c\)!
  • Consequently, both \(M_0\) and \(M_0^c\) would reject the string, violating complementation.
  • By adding \(q_{dead}\) to consume all trailing characters and initializing the stack with \(Z_0\) to prevent stack-underflow hanging, \(M\) is guaranteed to read every input string to its end, making state-swapping valid.

Question 10 (Formal Proof: Non-Determinism of \(ww^R\))

Prove that the language \(L_{pal} = {w w^R \mid w \in {0, 1}^*}\) is not a Deterministic Context-Free Language (DCFL).

💡 View Solution

Mathematical Proof

Suppose for contradiction that \(L_{pal} = {w w^R \mid w \in {0, 1}^*}\) is a DCFL.

  1. Closure under Complementation: By Theorem 2.42 (Sipser), the class of DCFLs is closed under complementation. Therefore, if \(L_{pal}\) is a DCFL, its complement: \[\bar{L}_{pal} = {x \in {0,1}^* \mid x \neq w w^R \text{ for any } w}\] must also be a DCFL (and hence a CFL).

  2. Intersection with a Regular Language: Context-free languages (and DCFLs) are closed under intersection with regular languages. Let \(R\) be the regular language: \[R = L(0^* 1 0^* 1 0^* 1 0^*)\] (the set of all binary strings containing exactly three \(1\)’s).

  3. Analyze the Intersection \(L_{int} = \bar{L}_{pal} \cap R\): Consider a string \(x \in R\) containing three \(1\)’s. Such a string can be written as: \[x = 0^i 1 0^j 1 0^k 1 0^m \quad \text{for } i, j, k, m \ge 0\]

    • For \(x\) to be of the form \(w w^R\), \(x\) must have an even length and its sequence of \(1\)’s must be symmetric. But \(x\) contains exactly three \(1\)’s (an odd number of \(1\)’s)!
    • A string with an odd number of \(1\)’s can never be decomposed into \(w w^R\), because \(w w^R\) contains \(n_1(w) + n_1(w^R) = 2 n_1(w)\) \(1\)’s, which is always even.
    • Therefore, no string in \(R\) can belong to \(L_{pal}\).
    • This implies that every string in \(R\) belongs to the complement \(\bar{L}_{pal}\)!
    • Thus, the intersection is simply: \[L_{int} = \bar{L}_{pal} \cap R = R = L(0^* 1 0^* 1 0^* 1 0^*)\]
    • Since \(R\) is regular, \(L_{int}\) is regular.

  4. Alternative Classic Proof using \(L’ = {a^i b^j c^k}\): Let’s consider another formulation using endmarkers. Let \(L_{marked} = {w $ w^R \mid w \in {0, 1}^*}\). \(L_{marked}\) is a DCFL. But for \(L_{pal}\) without \($\), suppose a DPDA \(M\) recognizes \(L_{pal}\).

    • Consider inputs \(w_k = 0^k 1 1 0^k \in L_{pal}\). \(M\) must enter an accept state after reading \(0^k 1 1 0^k\).
    • Now consider extending \(w_k\) to \(w’k = 0^k 1 1 0^k 0^k 1 1 0^k \in L{pal}\).
    • Since \(M\) is deterministic, after accepting \(w_k\), it must continue reading \(0^k 1 1 0^k\) and accept again.
    • By the Pumping Lemma for DPDAs, \(M\) cannot maintain distinct stack configurations for all prefixes \(0^k\) without popping them upon reading \(11\). Once \(M\) pops its stack to verify \(w_k\), its stack memory of \(0^k\) is destroyed. It cannot subsequently verify the second half \(0^k 1 1 0^k\).
    • This contradiction proves that \(L_{pal} = {w w^R \mid w \in {0, 1}^*}\) is not a DCFL. \(\blacksquare\)
